# 실제 지도 엔진을 연결한 iPhone 시험

기존 여행색칠과 다른 `app.trippainting.maplibreqa` 앱입니다. MapLibre 6.31.0으로 작은 합성 지도를 읽습니다. 계정, 사진, 방문과 위치 기록은 연결하지 않습니다. 지도 캐시도 이 앱의 저장 공간에 새로 생깁니다.

2026-10-31 실제 iPhone의 signed Debug 앱에서 두 가지를 확인했습니다.

- 합성 스타일과 256px 타일을 받고, 예상한 지도 소스와 레이어 및 SDK의 렌더 완료 콜백을 확인했습니다. 시험용 요청 변환이 `/entry`를 `/sdk`로 바꾼 뒤 기존 통신 제한 경로를 거쳤습니다. 서버에는 합성 인증과 쿠키가 전달되지 않았습니다.
- 다른 호스트를 가리키는 타일을 SDK가 요청했을 때 실제 전송 전에 거절했습니다. 이 단계에서 서버에 간 요청은 합성 스타일 하나뿐이었습니다.

처음 네트워크 허용을 기다리다 끝난 준비는 지도 요청이 0건이어서 통과 수에 포함하지 않았습니다. 허용 뒤 새 프로세스와 새 시험 이름으로 위 두 검사를 마쳤습니다. 결과와 장부 3개를 대조해 보관하고 시험 앱과 서버를 제거했습니다. 원래 여행색칠의 설치 정보는 같으며 개인 DB, 사진과 인증을 열거나 새로 대조하지 않았습니다.

## 범위는 여기까지입니다

이 결과는 작은 네이티브 SDK 시험입니다. 실제 React Native 요청 변환 모듈, 글꼴과 아이콘, 여러 타일의 동시 처리, TLS/HTTP2, 오프라인 팩과 OS 수신량 상한은 아직 확인하지 않았습니다. 렌더 완료는 SDK 콜백으로 확인했으며 픽셀 검사나 사용자의 화면 확인 결과로 세지 않습니다. 공개 지도 공급원에는 요청하지 않았고 제품 앱에도 연결하지 않았습니다.

`MLNNetworkConfiguration`의 기존 delegate 역할은 강하게 보관한 시험용 객체로 대신했습니다. 세션 설정을 바꿔도 같은 객체가 유지되고 주소 변환이 서버 도착 경로에 반영되는지 확인했습니다. 실제 RN 모듈을 연결한 증거로 대신하지 않습니다. 설정은 `MLNMapView`와 기본 지도 저장소를 만들기 전에 적용하고 명시적인 합성 스타일로 시작합니다. 위치 표시와 위치 권한 요청은 꺼 둡니다.

## 다시 빌드하려면

`APPLE_TEAM_ID`에 기존 개발 서명 팀을 지정하고 실행합니다.

```sh
bash qa/map-transport/ios-maplibre/build-ios.sh
```

`dependency.json`은 제품에 선언된 것과 같은 6.31.0의 공식 dynamic SDK 주소, 크기와 SHA-256을 고정합니다. `prepare-sdk.py`는 약 10.3MB 압축 파일을 대조하고 실제 아이폰용 약 8.8MB만 준비합니다. 기존 Pods/SPM과 앱 의존성은 바꾸지 않습니다. SDK의 BSD 라이선스도 앱에 포함합니다. 다운로드와 SDK, 서명·빌드 출력은 모두 Git 제외 `.build/`에 둡니다.

실행할 때 `QA_SERVER_ORIGIN`과 새 `QA_RUN_ID`를 전달합니다. 서버는 [sdk-server.mjs](../fixture/sdk-server.mjs)이며 명시적으로 허용한 사설 IPv4의 HTTP만 받습니다. 이미 사용한 시험 이름은 거절하고 결과 파일도 덮어쓰지 않습니다. 현재 앱의 재실행 보존 검사는 별도 범위입니다.

원문 근거는 로컬 Git 제외 `docs/test-results/maplibre-sdk-qa-20261031/`에 있습니다. 다음은 [재개 순서](../../../docs/RESUME.md)와 [제품 연결 전 조건](../../../docs/OFFLINE_MAP_TRANSPORT.md)을 따릅니다.
