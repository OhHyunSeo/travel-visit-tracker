## 배경지도 선정과 실제 시험의 구분

10월 30일 별도 iPhone 시험 앱의 시작을 수정하고 실제 아이폰의 기본 11개, 완료 후 홈 복귀와 실제 강제 종료 후 새 프로세스 재실행 2개를 통과했습니다. Android 환경 보호의 호스트 25개도 통과했습니다. 새 Android native와 MapLibre 통합, OS 수신량 상한의 검증은 아닙니다. 과거 AVD QCOW2 차이도 원인이 미확정입니다. 사용자 요청으로 이 지점을 저장, 중단하며 아래 수용 판정은 유지합니다.

10월 29일 후속 별도 전송 도구의 합성 서버 11개와 Android API37 Debug 여섯 묶음을 통과했습니다. iPhone은 화면 시작 중 종료돼 통신 대상 NOT RUN이며 Android AVD QCOW2 보존 차이도 미해결입니다. 제품 MapLibre와 실제 수신량 상한을 검증한 결과가 아니므로 아래 실기기 수용 판정을 바꾸지 않습니다. 사용자 요청으로 [현재 지점](../qa/map-transport/README.md)을 저장하고 중단했습니다.

10월 29일 P3-02의 공통 사전 계산과 저장 내용 대조 50개를 추가했습니다. 양쪽 운영체제는 소스 검토만 수행했으며 실제 SDK 다운로드, 공급원 요청 제한과 네이티브 통제 서버 시험은 아직 NOT RUN입니다. [요청 경로와 저장소 격리 조건](OFFLINE_MAP_TRANSPORT.md)을 기록했고 아래 실기기 판정은 유지합니다.

10월 28일 P3-01에서 OpenFreeMap, Liberty와 이용 범위를 선정했습니다. 전체 설계 작업 수는 24/54가 됐지만 실제 타일 다운로드, 오프라인 지도 표시나 G1~G4 통과를 뜻하지 않습니다. 요청 제어, 별도 지도 팩과 비행기 모드 검사는 P3-02~04에 남으며 아래 기기 시험 판정은 바꾸지 않습니다. [선정 문서](OFFLINE_MAP_PLAN.md)에 구현 전 조건을 정리했습니다.

## 최근 백업 검사에서 확인한 범위

10월 28일 다음 묶음에서는 공통 파일 오류와 반복 누적 회귀 10개, 실제 iPhone의 다섯 사례를 통과했습니다. native 폴더 생성과 marker 쓰기의 ENOSPC, 읽기 EIO, 삭제 EACCES는 지정 QA 경로에만 주입한 예외입니다. 오류 뒤 정상 재시도와 원본, DB, 대기를 보존했고, 보존 대상 25개를 둔 상태에서 세 묶음 36개를 처리했습니다. 공통은 65개를 보존하며 열 묶음 120개를 처리했고 전체 verifier 559/61과 양쪽 JS/Hermes가 통과했습니다. Android의 같은 다섯 사례와 원본, 환경 복구도 통과했으며 `90318b4`와 CI40685125473에 저장했습니다. 실제 OS 디스크 부족, 여러 날 경과, 새 실제 재시작과 Release 검증은 별도이며 아래 수용 판정은 유지합니다.

10월 28일에는 제품 `ef799c4`의 실제 iPhone Debug 앱에서도 임시 사본 정리 한도 두 개를 확인했습니다. 실제 native 생성, 서버 ACK, SQLite guard를 사용해 21개를 20개와 1개로 처리하고, 이미지 67,108,863바이트를 읽은 뒤 다음 차례로 넘겼습니다. 다음 패스에서 ACK가 없는 사본과 대기는 보존했습니다. 이전 session marker만 합성한 결과로 새 실제 재시작, 장기 누적, 공간 부족이나 Release 증거는 아닙니다. 원래 모든 기록, 사진, 인증과 임시 소스, 환경 복구를 확인했고, 아래 수용 시험의 최종 판정과 전체 23/54는 바꾸지 않습니다.

10월27일에는 `ef799c4`의 새 소스 컴파일 Debug 앱을 실제 iPhone에 업데이트하고 빈 v5/인증/파일/HTTP 및 서버 TCP 복구 후 foreground 주기 확인1개를 통과했습니다. 긴 retry보다27,966ms 먼저 같은 방문1개로 완료했고 사진은 보내지 않았습니다. 설치 전후 새 native 인증 대조와 모든 기존 DB행/사진 보존, 변경된 iOS 컨테이너에서 상대 경로의 제품 resolver 동작도 확인했습니다. 같은 소스의 Android에서는 합성 이전-session marker21개에 대한20개 검사/다음 패스와64MiB 이미지 읽기 한도/ACK guard2개를 확인했습니다. 새 실제 재시작이나 물리 Android/Release 결과는 아닙니다.

이어 iPhone 가입/정확한16KiB/1바이트 초과 경계3개도 통과했습니다. 정상 백엔드가 저장한 가입 응답16/339바이트를 native로 관측하고10,006ms에 실패/대기 해제와 기존 인증/행/사진을 보존했습니다. 같은 이메일409와 정상 로그인도 확인했습니다. Content-Length 없는16,384바이트는 실제 reader3회/85ms에 성공,16,385바이트는2회/84ms에 거부됐으며 기존 인증 보존과 다음 정상 확인을 통과했습니다. 모든 abort/cancel/release를 전달했고 두 경계의 reader cancel/release 호출은 각각1회입니다. 초기 잠금과 compression/게이트 준비 오류는 통과 수에서 제외하고 정상 백엔드 앞 TCP 중계로 재검증했습니다. 손가락 UI나 큰 본문 스트레스/Release 증거로 확대하지 않습니다. 사용자 요청으로 현재 부분까지 저장/중단하며 다음 iPhone 정리 한도는 미실행입니다.

일부 과거 이력의 상세 파일은 개인정보를 포함해 원래 PC의 Git 제외 폴더에 보관합니다. 다른 PC나 GitHub에서는 [공유 진행 기록](../PROGRESS.md)과 각 PR의 요약을 기준으로 확인합니다.

## 1. 시험 전제

- 빌드 버전, 소스 스냅샷, 경계 팩 버전, 지도 공급원을 기록한다.
- iPhone과 Android 실제 기기에서 각각 실행한다. 시뮬레이터 결과만으로 위치·배터리 시험을 통과시키지 않는다.
- 사용자 A/B 테스트 계정과 별도 테스트 서버를 준비한다. 실제 사용자 데이터로 유실 시험을 하지 않는다.
- 오프라인 시험은 경계 팩과 배경 지도 다운로드 상태를 구분한다.
- 자동 테스트의 300초 경계와 실기기의 위치 전달 지연을 구분한다. 실기기가 정확히 300초에 알림을 준다고 가정하지 않는다.
- GPS 정확도, 최대 관측 공백, 배터리 허용치는 P2에서 근거를 갖고 확정한다. 미정 상태로 해당 시험을 PASS 처리하지 않는다.

## 3. 판정 규칙

- **PASS:** 기대 결과를 충족하고 재현 절차·환경·증거를 기록했다.
- **PARTIAL:** 절차 일부만 확인했거나 필요한 기기와 프로필이 남았다. 통과한 부분과 남은 부분을 함께 적는다.
- **FAIL:** 기대 결과와 다르다. 문제, 재현 조건, 수정 작업 ID를 기록한다.
- **NOT RUN:** 실행하지 않았다. 구현되었다는 설명만으로 바꾸지 않는다.
- **BLOCKED:** 기기, 권한, 환경 등 구체적인 선행 조건 때문에 실행할 수 없다. 해결 조건을 적는다.

강제 종료 뒤에도 항상 위치를 수집해야 한다는 기준은 두지 않는다. 실제 운영체제에서 수집이 중단되는 조건과 복구 동작을 확인하고 사용자에게 정확히 표시한다. 지원하기로 한 화면 잠금 상태에서 기록이 누락되는 문제는 별도로 수정한다.

초기 README의 배터리 목표는 검증된 성능이 아니다. P2-12에서 환경, 위치 정책, 허용 수치를 정하고 AT-12에 반영한다. 성능 목표 역시 초기 측정 후 숫자로 정한다.

방문 판정 오류, 영속 기록·사진 유실, 사용자 데이터 혼합, 중복 동기화 또는 삭제 복원 문제는 배포 후보 통과를 막는다. 외부 지도 공급원이나 OS 제약은 범위·대응을 기록하고 제품 동작과 안내에 반영한다.
