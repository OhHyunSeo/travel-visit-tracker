# 수용 시험과 실기기 증거

작성일: 2026-10-11, 최근 갱신: 2026-10-16

연결 문서: [개발 계획](../PROJECT_PLAN.md), [진행 기록](../PROGRESS.md)  
현재 결과: **AT-01 iOS 개발 빌드 PASS, AT-08·15·16·17·18 iOS 부분 검증. 나머지 필수 실기기 시나리오는 검증 대기.** 가상 기기의 부분 검증과 실제 휴대폰 수용 결과를 구분한다.

## 1. 시험 전제

- 빌드 버전, 소스 스냅샷, 경계 팩 버전, 지도 공급원을 기록한다.
- iPhone과 Android 실제 기기에서 각각 실행한다. 시뮬레이터 결과만으로 위치·배터리 시험을 통과시키지 않는다.
- 사용자 A/B 테스트 계정과 별도 테스트 서버를 준비한다. 실제 사용자 데이터로 유실 시험을 하지 않는다.
- 오프라인 시험은 경계 팩과 배경 지도 다운로드 상태를 구분한다.
- 자동 테스트의 300초 경계와 실기기의 위치 전달 지연을 구분한다. 실기기가 정확히 300초에 알림을 준다고 가정하지 않는다.
- GPS 정확도, 최대 관측 공백, 배터리 허용치는 P2에서 근거를 갖고 확정한다. 미정 상태로 해당 시험을 PASS 처리하지 않는다.

## 3. 판정 규칙

- **PASS:** 기대 결과를 충족하고 재현 절차·환경·증거를 기록했다.
- **FAIL:** 기대 결과와 다르다. 문제, 재현 조건, 수정 작업 ID를 기록한다.
- **NOT RUN:** 실행하지 않았다. 구현되었다는 설명만으로 바꾸지 않는다.
- **BLOCKED:** 기기, 권한, 환경 등 구체적인 선행 조건 때문에 실행할 수 없다. 해결 조건을 적는다.

강제 종료 뒤에도 항상 위치를 수집해야 한다는 기준은 두지 않는다. 실제 운영체제에서 수집이 중단되는 조건과 복구 동작을 확인하고 사용자에게 정확히 표시한다. 지원하기로 한 화면 잠금 상태에서 기록이 누락되는 문제는 별도로 수정한다.

초기 README의 배터리 목표는 검증된 성능이 아니다. P2-12에서 환경, 위치 정책, 허용 수치를 정하고 AT-12에 반영한다. 성능 목표 역시 초기 측정 후 숫자로 정한다.

방문 판정 오류, 영속 기록·사진 유실, 사용자 데이터 혼합, 중복 동기화 또는 삭제 복원 문제는 배포 후보 통과를 막는다. 외부 지도 공급원이나 OS 제약은 범위·대응을 기록하고 제품 동작과 안내에 반영한다.
