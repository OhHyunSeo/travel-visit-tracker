# Trip Painting

다녀온 곳이 하나씩 칠해지는 지도입니다. 한 지역에 머문 방문을 기록하고, 그곳에서 남긴 사진을 함께 모아 볼 수 있는 Android, iOS 앱을 만들고 있습니다.

프로젝트의 한국어 이름은 **발걸음 추적기**입니다. 현재는 GPS로 방문을 확인하며, 걸음 수 센서나 건강 앱 연동은 아직 추가하지 않았습니다.

## 어떻게 기록하나요?

1. 앱에서 자동 방문 기록을 켭니다.
2. 한 지역에서 정확한 위치 관측이 5분 이상 이어지면 방문을 저장하고 지도에 색을 채웁니다.
3. 기록 목록에서 지역을 열어 방문 날짜와 사진을 봅니다.

같은 지역을 여러 번 방문해도 목록에는 카드 하나로 모입니다. 개별 방문 내역과 사진은 상세 화면에 남습니다. 위치가 오래 끊기거나 오차가 크면 체류 확인을 다시 시작하지만, 이미 저장한 방문은 유지합니다.

## 지금 어디까지 됐나요?

지도, 방문 판정, 사진 보관과 수집 현황을 구현했습니다. 실제 아이폰의 정지 상태 30분 잠금과 Android 에뮬레이터의 30분 화면 꺼짐에서 기록 보존을 확인했습니다. 실제 이동과 배터리, 출시용 빌드 검사는 남아 있습니다.

로그인은 선택 사항입니다. 계정에 보관한 방문은 **방문 백업하기**로 서버에 보낼 수 있습니다. 자동 방문 백업은 처음에는 꺼져 있고, 계정마다 안내를 확인한 뒤 켤 수 있습니다. 켜 두면 앱을 화면에 열어 둔 동안 전송합니다.

로그인이나 계정 확인 응답이 늦어지면 제한 시간 뒤 다시 시도할 수 있습니다. 연결 문제로 기존 계정의 기록을 옮기거나 지우지 않으며, 대기 중이던 계정 동작도 이어갈 수 있게 했습니다.

사진은 **사진 백업하기**에서 매번 계정과 서버, 전송 범위를 확인한 뒤 수동으로 보냅니다. 방문을 먼저 보내고 앱에 보관된 JPEG, PNG 첨부본을 그대로 전송합니다. 기기의 사진은 남겨 두며 자동 방문 백업에는 사진이 포함되지 않습니다.

**기록 복원하기**에서는 서버에 보낸 방문과 사진을 받을 수 있습니다. 한 번에 새 사진은 최대 20개씩 받습니다. 이전에 받은 사진이 손상되거나 사라진 경우도 점검해 새 사본으로 복구합니다. 기존 파일과 아직 보내지 않은 변경은 보존합니다. 보내지 않은 기록과 미지원 사진은 기기에만 남으므로 앱을 삭제하기 전에 확인해 주세요.

연결이 끊기면 작업을 기기에 남기고 다시 시도할 수 있습니다. 실제 아이폰과 Android 에뮬레이터에서 전송 실패 뒤 같은 작업을 다시 보내도 사진이 중복되지 않는 것을 확인했습니다. 복원 응답이 끝나지 않는 경우도 제한 시간이 지나면 대기를 남기고 다시 시도할 수 있습니다. 이 보완도 실제 아이폰과 Android 에뮬레이터의 별도 저장소에서 확인했습니다.

방문 백업이 완료 응답을 오래 기다리는 경우에도 제한 시간이 지나면 다시 시도할 수 있습니다. 이미 서버에 저장된 방문을 다시 보내도 중복되지 않도록 같은 작업으로 확인합니다.

앱 종료 후 전송용 임시 사본이 남으면, 서버 저장이 확인됐고 기기에 같은 원본이 있는 새 형식의 사본만 다시 시작할 때 정리합니다. 사용 중이거나 출처가 불명확한 사본은 보존합니다. 이 동작도 실제 아이폰과 Android 에뮬레이터에서 확인했습니다.

저장 구조를 바꿀 때도 예전 기록과 사진 경로를 보존하도록 검사하고 있습니다. 기기 검사는 기존 자료와 분리한 시험용 저장소를 사용합니다. 확인한 범위와 남은 검사는 [진행 기록](PROGRESS.md)에 구분해 적었습니다.

전체 계획의 **54개 작업 중 24개**를 완료했습니다. 자세한 상태는 [체크리스트](docs/CHECKLIST_STATUS.md)에서 볼 수 있습니다.

지도는 공개 경계 자료를 앱에 담아 사용합니다. 현재 팩은 2020년 기준 228개 지역이며, 최신 행정구역과 차이가 있을 수 있습니다. [자료 출처와 라이선스](travel_visit_tracker/src/data/README.md)를 함께 확인해 주세요.

배경 도로지도는 OpenFreeMap의 Liberty 스타일을 사용하기로 정했습니다. 현재 앱에는 경계 지도가 표시되며, 지역별 배경지도 저장 기능은 다음 단계에서 연결합니다. 무료 사용 범위와 다운로드 제어 조건은 [배경지도 방향](docs/OFFLINE_MAP_PLAN.md)에 정리했습니다.

## 개발 환경에서 실행하기

Node **24.21.0**을 사용합니다. 저장소를 받은 뒤 루트 폴더에서 실행하세요.

```sh
nvm install
nvm use
bash scripts/setup-cloud.sh
bash scripts/verify-cloud.sh
```

이 명령으로 의존성을 설치하고 타입, 코드 스타일, 자동 테스트와 양쪽 플랫폼의 JS 번들을 확인합니다. 휴대폰 앱을 실행하려면 Expo 개발 빌드와 각 플랫폼의 개발 도구가 필요합니다.

- [모바일 앱 실행](travel_visit_tracker/README.md): Android SDK, iPhone 서명과 개발 서버 연결
- [서버 실행과 API](backend/README.md): 인증, 방문 백업과 사진 저장
- [PC와 Cloud에서 이어서 개발하기](docs/CLOUD_DEVELOPMENT.md): 환경 변수, 네트워크와 Git 작업 흐름

## 코드는 어떻게 나뉘어 있나요?

| 폴더 | 담고 있는 것 |
| --- | --- |
| `travel_visit_tracker/` | Expo, React Native, TypeScript로 만든 현재 앱 |
| `backend/` | Express, SQLite 기반의 백업 서버 |
| `docs/` | 방문 판정 기준, 검사 기록, 개발 안내 |
| `scripts/` | 공통 설치와 검사 도구 |
| `prototype_reference/`, `travel_visit_tracker_flutter_backup/` | 이전 구현을 참고하기 위해 보관한 소스 |

현재 앱은 MapLibre로 지도를 그리고, SQLite에 기록을 보관합니다. 자세한 개발 순서는 [개발 계획](PROJECT_PLAN.md), 방문 확정 기준은 [방문 정책](docs/VISIT_POLICY.md)에 있습니다.

개인 DB와 사진, 환경 비밀값, 서명 파일과 백업은 GitHub에 올리지 않습니다. 기기에서 확인한 원본 자료는 원래 PC에 보관하고, 공유 문서에는 결과 요약을 남깁니다. [개발 규칙](AGENTS.md)과 [MIT License](LICENSE)도 참고해 주세요.
