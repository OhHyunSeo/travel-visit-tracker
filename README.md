# Trip Painting

다녀온 곳이 하나씩 칠해지는 지도입니다. 한 지역에 머문 방문을 기록하고, 그곳에서 남긴 사진을 함께 모아 볼 수 있는 Android, iOS 앱을 만들고 있습니다.

프로젝트의 한국어 이름은 **발걸음 추적기**입니다. 현재는 GPS로 방문을 확인하며, 걸음 수 센서나 건강 앱 연동은 아직 추가하지 않았습니다.

## 어떻게 기록하나요?

1. 앱에서 자동 방문 기록을 켭니다.
2. 한 지역에서 정확한 위치 관측이 5분 이상 이어지면 방문을 저장하고 지도에 색을 채웁니다.
3. 기록 목록에서 지역을 열어 방문 날짜와 사진을 봅니다.

같은 지역을 여러 번 방문해도 목록에는 카드 하나로 모입니다. 개별 방문 내역과 사진은 상세 화면에 남습니다. 위치가 오래 끊기거나 오차가 크면 체류 확인을 다시 시작하지만, 이미 저장한 방문은 유지합니다.

## 지금 어디까지 됐나요?

지도, 방문 판정, 사진 보관, 수집 통계와 기기 안의 저장 기능을 구현했습니다. 실제 아이폰의 정지 상태 30분 잠금과 Android 에뮬레이터의 30분 화면 꺼짐에서 기록 보존을 확인했습니다. 실제 이동과 배터리, 출시용 빌드는 더 확인해야 합니다.

설정에서 선택적으로 로그인하고, 계정에 보관한 방문을 **방문 백업하기**로 서버에 보낼 수 있습니다. 자동 방문 백업은 계정마다 처음에는 꺼져 있으며, 안내를 확인하고 켜면 앱을 화면에 열어 둔 동안 전송합니다. 연결에 실패한 작업은 기기에 남기고, 앱을 열어 둔 동안 서버 연결을 다시 확인해 전송을 이어갑니다. 같은 방문을 반복 전송해도 중복 저장하지 않습니다.

사진은 **사진 백업하기**에서 계정·서버와 전송 범위를 확인한 뒤 수동으로 보냅니다. 방문을 먼저 전송하고 앱에 보관된 JPEG·PNG 첨부본을 그대로 보냅니다. 지원하지 않거나 없는 파일은 대기에 남으며 기기의 사진도 유지합니다. 자동 방문 백업에는 사진이 포함되지 않습니다.

아이폰과 Android 에뮬레이터의 로그인·방문 백업 일부 검증은 완료했습니다. 사진도 양쪽의 실제 파일·별도 시험 DB·임시 서버로 전송과 중복 없는 재시도를 확인했습니다. 합성 사진 1건이 있는 시험 계정에서 취소, 확인 후 전송, 다음 실행의 재확인까지 검증했습니다. 아이폰의 확인 버튼은 사용자가 직접 눌렀고 Android는 에뮬레이터 화면에서 검사했습니다. **기록 복원하기**에서 서버에 보낸 방문과 JPEG, PNG 사진을 수동으로 받는 기능을 추가했습니다. 새 복원은 자동 검사와 임시 서버, 실제 아이폰의 파일·화면에서 확인했습니다. Android 에뮬레이터에서도 새 복원과 정상 앱 재실행을 확인했습니다. 복원 완료 뒤 파일이 손상되거나 사라졌을 때도 다시 받을 수 있도록 보완했습니다. 수동 복원 때 이전 다운로드를 최대 20개씩 확인하고, 문제가 있으면 기존 파일을 보존한 새 사본으로 연결합니다. 이 보완의 자동 검사와 Android 에뮬레이터 검사는 통과했습니다. 아이폰의 새 보완 검사는 잠금 해제 뒤 진행합니다. 자동 사진 전송은 아직 없습니다. 보내지 않은 기록과 지원하지 않는 사진은 기기에만 남으므로 앱 삭제 전에 확인해 주세요.

전체 계획의 **54개 작업 중 23개**를 완료했습니다. 자세한 상태는 [체크리스트](docs/CHECKLIST_STATUS.md), 최근 변경은 [진행 기록](PROGRESS.md)에 정리했습니다.

복원을 준비하면서 계정마다 같은 식별자의 기록을 따로 보관할 수 있도록 저장 구조도 보강했습니다. 예전 기록과 사진 경로를 유지하는 자동 검사와 iPhone·Android 에뮬레이터의 별도 저장 검사를 마쳤습니다. 복원 대기와 조회 위치도 기기에 보관하며, 다운로드가 끊기면 다시 눌러 이어받을 수 있습니다. 기존 기록이나 사진을 덮어쓰지 않고, 서버에서 삭제된 방문은 숨깁니다.

지도는 공개 경계 자료를 앱에 담아 사용합니다. 현재 팩은 2020년 기준 228개 지역이며, 최신 행정구역과 차이가 있을 수 있습니다. [자료 출처와 라이선스](travel_visit_tracker/src/data/README.md)를 함께 확인해 주세요.

## 개발 환경에서 실행하기

Node **24.21.0**을 사용합니다. 저장소를 받은 뒤 루트 폴더에서 실행하세요.

```sh
nvm install
nvm use
bash scripts/setup-cloud.sh
bash scripts/verify-cloud.sh
```

이 명령으로 의존성을 설치하고 타입, 코드 스타일, 자동 테스트와 양쪽 플랫폼의 JS 번들을 확인합니다. 휴대폰 앱을 실행하려면 Expo 개발 빌드와 각 플랫폼의 개발 도구가 필요합니다.

- [모바일 앱 실행](travel_visit_tracker/README.md): Android SDK, iPhone 서명과 개발 서버 연결
- [서버 실행과 API](backend/README.md): 인증, 방문 백업과 사진 저장
- [PC와 Cloud에서 이어서 개발하기](docs/CLOUD_DEVELOPMENT.md): 환경 변수, 네트워크와 Git 작업 흐름

## 코드는 어떻게 나뉘어 있나요?

| 폴더 | 담고 있는 것 |
| --- | --- |
| `travel_visit_tracker/` | Expo, React Native, TypeScript로 만든 현재 앱 |
| `backend/` | Express, SQLite 기반의 백업 서버 |
| `docs/` | 방문 판정 기준, 검사 기록, 개발 안내 |
| `scripts/` | 공통 설치와 검사 도구 |
| `prototype_reference/`, `travel_visit_tracker_flutter_backup/` | 이전 구현을 참고하기 위해 보관한 소스 |

현재 앱은 MapLibre로 지도를 그리고, SQLite에 기록을 보관합니다. 자세한 개발 순서는 [개발 계획](PROJECT_PLAN.md), 방문 확정 기준은 [방문 정책](docs/VISIT_POLICY.md)에 있습니다.

개인 DB와 사진, 환경 비밀값, 서명 파일과 백업은 GitHub에 올리지 않습니다. 기기에서 확인한 원본 자료는 원래 PC에 보관하고, 공유 문서에는 결과 요약을 남깁니다. [개발 규칙](AGENTS.md)과 [MIT License](LICENSE)도 참고해 주세요.
