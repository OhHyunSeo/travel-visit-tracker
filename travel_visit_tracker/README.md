# Trip Painting 모바일 앱

이 폴더에는 지도, 방문 기록, 사진, 수집 현황과 설정 화면이 있습니다. 위치가 들어올 때마다 체류 조건을 확인하고, 확정한 방문과 전송 대기 작업을 SQLite에 함께 저장합니다. 사진은 임시 파일에 의존하지 않도록 앱의 저장 폴더에 복사합니다.

같은 지역의 방문은 기록 목록에서 하나로 모아 보고, 상세 화면에서는 각각의 방문 날짜를 확인할 수 있습니다. 설정의 **지금 기록 상태**에는 위치 정확도와 최근 수신 시각, 체류 확인을 다시 시작한 이유가 표시됩니다.

## 앱을 실행하려면

먼저 [루트 안내](../README.md)에 따라 Node 24.21.0과 의존성을 준비하세요. 다음 명령은 이 폴더에서 실행합니다.

```sh
npm run check
npm run ios
# Android를 실행할 경우
npm run android
```

지도와 위치 기능을 포함하므로 **Expo 개발 빌드**를 사용합니다. Android에는 SDK와 JDK 17, iPhone에는 Mac, Xcode와 Apple 서명 준비가 필요합니다. 네이티브 모듈이나 권한 설정을 바꿨다면 개발 빌드를 다시 만들어야 합니다.

이 Mac에서는 저장소 루트의 `.tooling/`에 Node와 JDK를 준비해 두었습니다. 로컬 경로와 실패했던 빌드 조합은 [개발 환경 기록](../docs/DEVELOPMENT_ENVIRONMENT.md)에 있습니다. JDK 25에서 Worklets 빌드가 실패했던 문제 때문에 현재 Gradle 기준은 config plugin으로 JDK 17을 유지합니다.

iPhone 서명 팀은 로컬 `.env.local`의 `APPLE_TEAM_ID`로 설정합니다. Apple 계정과 인증서는 Xcode에서 준비하며, 실제 값과 생성된 서명 파일은 커밋하지 않습니다.

iOS의 Expo 모듈은 현재 Xcode에서 직접 컴파일하도록 `app.config.ts`에 `usePrecompiledModules: false`를 선언했습니다. 다른 Swift SDK로 만든 사전 컴파일 인터페이스를 읽다 실패한 문제를 피하기 위한 설정이며, 바꾼 뒤에는 iOS 설정 재생성과 의존성 연결이 필요합니다. [Expo 공식 안내](https://docs.expo.dev/guides/prebuilt-expo-modules/)

아이폰에서 개발 앱을 더 이상 사용할 수 없다고 하면 개발용 서명 만료와 개발자 신뢰 상태를 확인합니다. 기록이 있는 앱을 삭제하지 말고 같은 앱 ID와 개발자로 업데이트한 뒤 기록 보존을 대조합니다. 최신 빌드와 기기 확인 범위는 [재개 안내](../docs/RESUME.md)를 따릅니다.

## 개발 서버 연결

설치된 개발 앱이 Mac의 Metro 서버에 연결되면 최신 JS 화면을 볼 수 있습니다. iPhone과 Android를 함께 개발할 때는 iPhone **8081**, Android **8082**를 사용합니다.

Android 에뮬레이터에서는 `adb reverse`로 localhost 서버를 연결할 수 있습니다. 현재 Android 전용 실행 도구와 데이터 보존 방식은 [Android PR #1](https://github.com/OhHyunSeo/travel-visit-tracker/pull/1)에 정리했습니다. 해당 도구가 포함된 Android worktree에서는 `npm run android:local`로 8082를 사용합니다. 공통 브랜치의 이전 실행 도구와 포트를 혼용하지 않도록 확인하세요.

iPhone은 Mac의 LAN 개발 서버에 연결합니다. 실제 네트워크 주소는 실행할 때 확인하며 공개 터널은 사용하지 않습니다. 연결 상태와 다음 검사 순서는 [재개 안내](../docs/RESUME.md)를 참고하세요.

웹은 화면과 로컬 기록을 미리 보는 용도입니다. 위치 수집과 사진, 잠금 중 동작은 휴대폰에서 확인합니다.

```sh
EXPO_OFFLINE=1 npm run web -- --localhost --port 8081
```

## 작업할 때 찾아볼 곳

| 폴더 | 역할 |
| --- | --- |
| `app/` | 지도, 기록, 수집 현황, 설정과 지역 상세 화면 |
| `src/domain/` | 경계, 체류 판정과 수집 통계 |
| `src/storage/` | 기록, 사진 연결과 전송 대기 작업 저장 |
| `src/services/` | 위치 권한, 수집 모드, 사진 보관과 계정·방문 백업 |
| `src/ui/` | 지도와 공통 화면 요소 |
| `tests/` | 저장과 판정이 바뀌지 않았는지 확인하는 검사 |
| `plugins/` | 네이티브 재생성 뒤에도 유지할 설정 |

## 현재 가능한 범위와 남은 확인

현재 경계는 [2020년 공개 개발 자료](src/data/README.md)이며 실제 228개 지역을 포함합니다. 경계는 연결 없이 볼 수 있지만 배경 도로 지도 다운로드는 아직 없습니다. 로그인, 계정별 방문 백업, 매번 확인하는 수동 사진 백업과 기록 복원을 사용할 수 있습니다. 받은 사진이 사라지거나 손상되면 점검 후 새 사본으로 복구하며, 기존 파일과 보내지 않은 변경은 보존합니다.

실제 아이폰과 Android 에뮬레이터에서 소스별로 확인한 범위는 [진행 기록](../PROGRESS.md)에 정리했습니다. 실제 Android 휴대폰, 출시용 빌드, 이동과 배터리, 전원/OS 비정상 종료와 전체 수용 시험은 남아 있습니다. 자동 사진 전송은 구현하지 않았습니다. 앱을 삭제하기 전에는 아직 기기에만 있는 방문과 사진을 확인해 주세요.

개발용 방문은 실제 GPS 방문과 구분하고 서버 전송 큐에 넣지 않습니다. 생산용 JS에서는 개발 입력과 개발 기록을 숨깁니다. JS 번들 검사를 통과해도 실제 기기의 이동, 배터리와 출시용 네이티브 빌드는 별도로 확인해야 합니다.

[전체 체크리스트](../docs/CHECKLIST_STATUS.md)와 [기기 시험 목록](../docs/ACCEPTANCE_TESTS.md)에 확인한 결과와 남은 작업을 기록하고 있습니다.


## 계정과 기록

설정에서 **로그인과 계정 설정**을 열어 서버 주소와 계정을 입력합니다. 로그인은 선택이며, 게스트 기록을 자동으로 가져오거나 서버로 보내지 않습니다. 계정을 바꾸면 위치 수집을 멈추고 해당 계정의 기기 기록을 엽니다. 자동 기록은 다시 켜 주세요.

게스트 GPS 방문과 사진은 **게스트 기록 가져오기**에서 대상 계정과 개수를 확인한 뒤 옮깁니다. 사진 파일과 방문 ID는 유지하며, 개발용 기록은 게스트 영역에 남깁니다. 옮긴 방문은 대상 계정의 백업 설정에 따라 전송됩니다. 로그인 정보가 만료돼도 계정의 기기 기록은 보존하고, 로그아웃하면 게스트 기록으로 돌아갑니다.

토큰은 SecureStore에 보관하며 SQLite나 웹 localStorage에는 저장하지 않습니다. iOS는 잠금 해제 상태에서만 접근하는 기기 전용 Keychain 설정을 사용합니다. Android의 SecureStore 자동 백업 제외를 config plugin에 선언했고 새 Debug APK의 규칙을 확인했습니다. 기존 앱에 업데이트 설치한 뒤 설치본도 확인했습니다. 새 APK의 전체 로그인 회귀와 실제 시스템 백업·복원 검사는 남아 있습니다. [SecureStore 공식 안내](https://docs.expo.dev/versions/latest/sdk/securestore/)

## 방문 백업

계정 화면의 **방문 백업하기**는 이 계정의 방문과 방문 삭제 요청을 전송합니다. **자동 방문 백업**은 계정별로 기본 꺼짐이며, 대상 계정과 서버 안내에 동의한 뒤 켤 수 있습니다. 앱이 화면에 열려 있을 때 시작·화면 복귀·4초마다의 점검에서 전송할 작업을 확인합니다. 연결 실패 시 다음 시도 시각을 저장하고 30초부터 최대 5분 간격으로 다시 시도합니다. 연결 실패 시에는 앱을 열어 둔 동안 약 30초 간격으로 서버 연결을 확인해 전송을 이어갈 수 있습니다. HTTP500 같은 서버 오류의 대기는 그대로 따릅니다. 401 인증 오류나 409 충돌이면 자동 재시도를 멈춥니다. 다시 로그인하거나 충돌을 확인한 뒤 수동으로 재시도할 수 있습니다.

화면의 대기 수는 방문의 개수가 아니라 **방문 변경사항의 수**입니다. 마지막 전송 완료 시각은 서버가 실제 방문 작업을 확인하고 방문 대기 목록이 비었을 때만 저장합니다. 사진 대기 작업은 별도로 표시하며 아래 사진 백업에서 수동으로 보냅니다. 방문 완료를 사진 전체 백업 완료로 표시하지 않습니다. 서버에 보낸 자료는 **기록 복원하기**에서 받을 수 있습니다.

아이폰에서는 직접 입력한 가입과 동의 화면을 확인했고, 별도 시험 저장소로 백업 실패와 같은 작업 재시도, 앱 복귀와 주기적인 연결 확인 뒤 자동 방문 전송을 검사했습니다. Android 에뮬레이터에서도 별도 저장소의 재시도와 계정 분리를 확인했습니다. 원래 개인 방문과 사진은 시험 서버로 보내지 않았습니다. 이 결과를 실제 Android 휴대폰이나 출시용 검증으로 대신하지 않습니다.


## 수동 사진 백업

**사진 백업하기**는 매 실행 대상 계정·서버와 전송 범위를 확인합니다. 방문을 먼저 전송하고 앱이 보관한 JPEG·PNG 첨부본을 보내며, 기기의 사진은 삭제하지 않습니다. 파일당 최대 10MiB이고 한 번에 최대 20개의 서버 저장을 확인합니다. 지원하지 않는 형식·없는 파일·크기 제한·서버가 거절한 손상 파일은 대기에 남기고 사유별 건수를 표시합니다. 건너뛴 요청을 포함한 실제 시도 수와 저장 확인 수는 다릅니다.

사진은 자동 방문 백업에 포함되지 않으며 실패 후에도 다음 수동 확인을 기다립니다. 서버가 계정, 작업, 사진과 방문, 바이트를 확인한 뒤 저장 확인과 대기 제거를 함께 적용합니다. 재시도해도 같은 사진을 중복 저장하지 않으며 기기 첨부본은 유지합니다. 앱 종료 후 남은 전송용 사본은 새 소유권 기록과 서버 확인, 현재 원본의 일치까지 확인한 경우만 정리합니다. 출처가 불명확한 이전 캐시는 보존합니다.

## 기록 복원

**기록 복원하기**는 계정과 서버, 받을 범위를 매번 확인한 뒤 방문과 사진을 받습니다. 새 사진은 한 번에 최대20개씩 받으며, 받은 사진의 누락이나 손상도 제한된 범위에서 점검합니다. 문제가 있는 다운로드는 새 파일로 복구하고 이전 파일과 사용자 첨부본은 남깁니다. 연결이 끊겨도 복원 대기와 조회 위치를 기기에 보관해 다시 시도할 수 있습니다.

현재 모바일 DB는 v5, 서버 DB는 v3입니다. 이전 저장 구조에서 계정별 기록과 사진 연결, 대기를 보존하도록 검사했습니다. 실제 아이폰의 확인창과 사진 표시, Android 에뮬레이터의 파일/저장/재시도 결과를 소스별로 구분해 기록하며, 실제 휴대폰 여러 대의 동시 변경과 전체 출시용 검증은 남아 있습니다.
